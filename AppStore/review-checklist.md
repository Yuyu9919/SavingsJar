# 提审前自检清单 & 被拒应对手册

> 攒钱类 App 的被拒率其实不高，**大部分驳回不是因为"功能不行"，而是因为"审核员看不懂这是什么"**。
> 下面这份清单按"检查→易错点→被拒了怎么办"组织，建议提交前逐条打勾。

---

## 一、提交前 32 项自检

### A. 技术类（会导致构建无法上传或被拒）

- [ ] 用 **Xcode 26 + iOS 26 SDK** 构建（2026/4/28 起的硬性要求，用旧 Xcode 传不上去）
- [ ] `MARKETING_VERSION` 与本次提审填写的版本号一致（如 `1.0.0`）
- [ ] `CURRENT_PROJECT_VERSION`（构建号）**大于**上一个已上传的构建号
- [ ] Release 配置归档，不是 Debug
- [ ] AppIcon 只有 1024×1024、**无透明通道**、**未预先切圆角**
- [ ] 归档时**没有**任何编译警告变成错误（尤其弃用 API 警告，会被追问）
- [ ] 已在真机上跑过一遍完整流程（模拟器跑通 ≠ 真机跑通）
- [ ] 在 iPhone SE 尺寸（小屏）上界面没有截断
- [ ] 深色模式下所有文字清晰可读
- [ ] 断网状态下 App 完全正常（本 App 不联网，更要确保没有任何超时转圈）
- [ ] 首次启动没有任何崩溃、白屏或明显卡顿
- [ ] `ITSAppUsesNonExemptEncryption` 已在 Info.plist 中声明为 `NO`
- [ ] 没有引用任何私有 API
- [ ] 应用启动后 5 秒内可用，没有强制引导/登录墙挡住审核员

### B. 元数据类

- [ ] App 名称无夸大词（"最强""第一""官方"等会被拒）
- [ ] 描述中提到的**每一个功能都真实存在**（描述功能与实际不符 = 2.3.1 虚假信息）
- [ ] 描述里没有写"免费"然后又用内购锁核心功能
- [ ] 截图内容与真实界面一致，**不能是纯设计稿或渲染图**
- [ ] 截图里没有出现其他品牌的 Logo、设备边框上的其他 App 图标
- [ ] 隐私政策 URL 可正常打开（**不能是 404、不能是需要翻墙的域名**）
- [ ] 技术支持 URL 可正常打开
- [ ] 两个 URL 都用了 HTTPS，且手机上打开排版正常
- [ ] 隐私政策内容与「App 隐私」问卷的选择**完全一致**
- [ ] 年龄分级问卷已按新版问完（2026/1/31 起强制）
- [ ] 版权信息格式正确（`© 2026 xxx`）

### C. 内容与合规类（攒钱类最容易踩的坑）

- [ ] **没有任何**真实资金流转（转账、支付、提现、充值）
- [ ] **没有**接入第三方支付 SDK
- [ ] **没有**出现"收益""回报率""年化""稳赚"等理财承诺词
- [ ] **没有**暗示本 App 能帮用户"赚钱"
- [ ] 描述中明确写了"仅为记录工具，不涉及真实资金交易"
- [ ] 审核备注里把上述声明又写了一遍（这一点极其重要，见下文）
- [ ] 没有收集用户数据却声明"不收集"
- [ ] 如果用了内购，价格展示与实际价格一致

### D. 审核备注类

- [ ] 「App 审核信息 ▸ 备注」栏已填写完整（`AppStore/metadata.md` 第五章可整段复制）
- [ ] 联系方式（邮箱 + 手机号）真实可用
- [ ] 如果需要登录，已提供演示账号 —— **本 App 不需要，直接在备注里说明"无需登录"**

## 二、攒钱类 App 最容易被卡住的 6 个点

| 被拒条款 | 触发原因 | 怎么避免 |
|---|---|---|
| **2.1 App 完整性** | 只放了个空壳、示例数据删不掉、功能点不开 | 确保每个按钮都有真实功能；示例数据可清除 |
| **2.3.1 隐藏功能 / 虚假信息** | 描述里的功能找不到，或隐私标签与实际不符 | 描述只写已实现的功能；隐私问卷逐项对代码核实 |
| **3.1.1 应用内购买** | 解锁高级版却用了非 StoreKit 的支付方式 | 一律走 StoreKit；iOS 内不允许跳转外部支付（除非符合最新外链规则） |
| **4.3 垃圾应用（Spam）** | 界面像模板套壳、功能过于单薄、和已有 App 高度雷同 | 突出差异化——多计划并行 + 5 种节奏 + 打卡网格就是你的差异点，截图里要体现出来 |
| **5.1.1 数据收集与存储** | 声明不收集却集成了统计 SDK | 保持零 SDK；以后加了必须回来更新隐私标签 |
| **5.1.2 数据使用与共享** | 用数据做广告或共享给第三方 | 本 App 不涉及 |

### 关于财务类的额外提醒

苹果对 **Finance 类** App 有额外门槛。如果只选财务类、又出现"存钱"字样，
审核员可能会要求你提供**金融业务资质证明**（如支付牌照）。

**规避方式（已写入 metadata.md）：**
1. 主类别选 **效率（Productivity）**，次类别选财务；
2. 审核备注里第一句就说清楚"这是个人目标追踪工具，不涉及真实资金"；
3. 描述末尾加免责声明（已写好）。

## 三、被拒了怎么办

### 3.1 先别慌：第一次被拒非常正常

- 收到的是 **App Review 的 Resolution Center 消息**，不是死刑判决；
- 苹果会给出**具体违反的条款编号**，比如 `Guideline 2.3.1 - Performance`；
- 你**不需要重新上传构建包**，只要修改文字/资源后重新提交即可（如果改了代码才需要重新传包）。

### 3.2 回复模板（直接在 Resolution Center 里回复）

针对最常见的"看不懂这是什么金融 App"驳回：

```
感谢审核团队的反馈。

关于 Guideline X.X.X 的疑虑，希望补充说明：

1. 攒钱罐是一款纯本地的个人储蓄目标追踪工具，功能定位等同于电子记账本。
   用户在其中记录的"金额"是用于自我追踪的数字，不具有金融价值。

2. 本 App 不提供、也不接入任何真实的资金服务：
   · 无支付、转账、提现、充值功能
   · 无银行、券商、第三方支付通道接入
   · 无投资建议、理财产品或任何收益承诺
   · 无账号系统，不收集任何用户数据

3. 已在本版本中采取以下调整（如适用）：
   · 将主类别由"财务"调整为"效率"
   · 在 App 描述末尾增加免责声明
   · 在审核备注中补充业务边界说明

如仍需补充材料，请告知具体需要哪一类，我们会尽快提供。
感谢！
```

### 3.3 如果被拒的是「4.3 Spam」

这条最伤，说明审核员认为你的 App 缺乏独特性。应对方式：

1. **在回复中列出差异化功能清单**（多计划并行 / 5 种储蓄节奏 / 52 周打卡网格 / 逾期自动标记），越具体越好；
2. **补一段 App 预览视频**，让审核员 30 秒内看到核心交互；
3. 如果确实是模板化界面，就得真改——换掉通用图标、加入至少一个别家没有的功能。

### 3.4 申请加急审核

如果被拒后已修复且紧急，可以申请加急（[加急申请表](https://developer.apple.com/app-store/review/expedited/)）。
**理由必须真实**，比如"已修复安全漏洞"。滥用加急会被拒。

## 四、审核时间预期

| 阶段 | 通常耗时 |
|---|---|
| 上传构建 → 出现在 App Store Connect | 15～30 分钟 |
| TestFlight 内部测试可用 | 几分钟 |
| TestFlight 外部测试（需审核） | 24 小时内 |
| 首次提交 App Store 审核 | **24～48 小时**（2026 年平均约 26 小时） |
| 被拒后重新提交 | 通常更快，12～24 小时 |
| 通过后正式上架 | 选择手动发布则由你控制，自动发布则几小时内 |

> 建议**首次提审留出一周缓冲**，别卡着节假日提。周四、周五提审遇到问题会拖到下周。

## 五、几个能让审核员心情变好的细节

1. **首屏不要放登录页。** 审核员最烦"要先注册才能看"。你的 App 无需登录，这是巨大优势。
2. **在备注里主动写出 3 步体验路径**，例如"点第一个计划卡片 → 点网格任意格子 → 完成"。
   审核员照着点一遍就能理解产品，通过率显著提升。
3. **截图第一张放最直观的界面**，别放启动页或品牌页。
4. **不要出现"敬请期待""即将上线"这类未完成字样**（会被判 2.1 不完整）。
5. 描述里**不要写其他平台**（"安卓版即将推出"这类会被要求删掉）。
